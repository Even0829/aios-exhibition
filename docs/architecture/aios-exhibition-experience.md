- 产品、设备和真实接入边界：[陈展事实与边界](../knowledge/products/aios-exhibition-context.md)。
- 四个完整体验故事：[陈展体验故事路由](exhibition-stories/README.md)。
- 包含通用、特殊和例外的完整 Demo 设计、还原与验收规范：[陈展设计系统与还原规范](../specs/aios-exhibition-design-system.md)。

本文件不再存放单个故事的全部页面、指标、文案或分支，避免与故事 Owner 形成第二定义。

## 2. 五类可交织运行状态

| 状态 | 含义 |
| --- | --- |
| 感知 | 持续获取人、空间和设备信息；思考、决策、执行和反馈期间仍存在 |
| 思考／分析 | 综合当前信息、理解状态或新事件，判断是否需要行动 |
| 决策 | 确定采取何种服务、调用何种能力，以及是否调整当前行动 |
| 执行 | 进行电视引导、设备调度、陪护或协同等服务行为 |
| 反馈 | 获取并表达设备回执、用户回应或可观察结果，为后续判断提供输入 |

五类状态不是互斥的五个页面步骤。一次典型事件可按“思考／分析→决策→执行→反馈”组织展示，但感知通常持续贯穿，新事件可在执行或反馈中再次触发分析。顶部中心组件按真实运行活动同时亮起多个状态。

主动确认是感知过程中的交互节点，不新增第六种运行状态。页面切换是展示编排，不能反向定义系统只有一个活动状态。

## 3. 共用体验契约

### 3.1 感知

**当前任务需要了解什么→按空间／人体组织感知需求→选取已有来源的设备能力→展示采集过程→呈现结果→衔接后续活动。**

- 空间感知与人体感知平级；当前先空间、后人体只是展示编排。
- 一次感知只调用当前任务需要且来源已确认的能力，不默认遍历全部设备。
- 设备是能力来源，结果按游客可理解的内容组织；不同设备的同类结果在规则确认前不自动融合。
- 采集完成只表示本轮数据已准备，不等于分析完成、健康判断或服务成功。

### 3.2 分析、决策、执行与反馈

- 分析必须区分设备测量、模型推断、用户回答、待执行动作和已确认结果；思考／分析页保持语音静默，但语音球以 `thinking` 动效表达系统正在理解。
- 决策先展示依据，再给出简短结论；右下角以更口语化的语音完整告知当前决策。
- 执行先建立目标，再展示设备或能力的调度步骤；目标卡不得冒充执行成功。
- 反馈必须由相应的 Mock 或真实证据驱动。指令已发出、设备已运行、指标已变化、联系人已确认和现场已接手是不同事实，不得互相代替。
- 页面语义由上游故事结果传入：正常倾向蓝色、普通异常倾向黄色、紧急倾向红色；组件不根据单个数值自行判断。
- 反馈颜色按执行后结果重新判定，不机械沿用事件初始等级。未解决或仍需升级的事件保持黄色或红色。

## 4. 事件优先级、中断与恢复

- 普通故事切换通过头像浮窗查验，并清理旧故事的页面计时、回答、进度和临时记忆，防止串场。
- 疑似跌倒是当前唯一已确认的全局紧急抢占事件。在已感知到人后，它可从任意故事或页面触发，暂停原自动翻页计时，并占用前景和唯一活动语音球。
- 紧急抢占不自动撤销原流程已发出的设备指令；保留的是业务页面和阶段，不是动画帧。
- 本人确认“我没事”后可记录并恢复原流程的稳定状态；求助或无人回应后进入红色持续守护，不自动恢复。
- 重启、切换故事或人工下一步只是 Demo 控制，不代表真实事件已解决。

## 5. 功能结构

| 入口 | 定位 | 当前范围 |
| --- | --- | --- |
| 主页 | 产品价值与游客体验主页面 | 承载默认故事与三个查验故事 |
| 空间 | 表达 INT AIOS 对空间的管理、感知与建模 | 空间场景包、空间建模空状态、其他实体 |
| 设备 | 浏览家庭设备、接入账号和当前状态，承接电视语音及基础遥控控制与手机配置 | 家庭设备／接入账号两栏；列表按空间筛选并在线优先，详情提供设备开关及适用的数值调节，添加与设置进入同面板手机二维码接续 |
| 记忆 | 浏览系统形成的可理解经验 | 短期／长期分类、列表与详情联动、语音拟修改 Mock |
| 电视 | 保留回到电视节目的入口意图 | Demo 只反馈“待接入”，不执行真实节目切换 |

空间、设备和记忆内页使用同一 `FeaturePanel` 开合契约：内页覆盖在当前流程之上，不重置底层运行状态；打开时当前主体模糊退场，展开语音先收合；关闭后恢复原稳定页面和未完成计时。设备内页进一步按“设备列表／设备详情／账号列表／手机接续”组织，账号卡进入对应账号的手机管理接续，不跳转关联设备筛选，也不新增电视账号详情页。电视列表只按空间收敛，不提供连接状态筛选；详情在语音之外提供设备开关和适用的程度数值调节，完整配置仍转手机。设备内的 Escape 每次只返回一层：语音澄清或确认→详情／手机接续→设备或账号列表→原流程；首页仍可关闭整个功能内页。疑似跌倒触发时，内页和设备语音必须让位紧急确认。设备中心完整产品规则由[设备中心 PRD](../specs/device-center-prd.md)统一定义。

## 6. 记忆与故事生命周期

- 记忆是从感知、服务结果、模型推断和用户确认中形成的可理解经验，不是原始调用日志后台。
- 首期短期状态为“新发现／验证中”，长期状态为“学习中／已形成／已沉淀”。完整事件、原始数据和调用历史默认不展开。
- 只有故事 Owner 定义的可收束结果才进入本轮记忆。未解决、等待介入或已升级的事件不预置成功记忆结论。
- 切换、重启和回流需清理当前故事回答、页面计时、进度、语音展开和临时记忆，不影响其他故事的基础配置。

## 7. 读取和更新规则

- 开展单个故事工作时，读取本文件、对应故事 Owner、完整设计系统和当前 Figma Direct Reference，不需要加载其余三个故事。
- 修改单个故事的触发、证据、流程、文案、分支、反馈或记忆时，只更新对应故事 Owner。
- 修改组件、配色、布局、转场、语音动效、特殊变体、例外或验收时，统一更新设计系统；故事 Owner 只保留场景配置和引用。
- 改变全局运行状态、故事优先级、中断恢复或功能结构时，更新本总架构。

当前仍未确认的全局问题包括：感知失败／超时／部分结果、体验者中途离开、多人关联、真实设备协议、外部通知、现场接手和真实持久化记忆。这些缺失不能用 Demo 动画或文案冒充为已接入能力。
