# 引元（INT AIOS）

## 知识地位与定位

**引元是官方称谓，核心定义是“物理空间 AI 操作系统”，即 INT AIOS。**

本文件是引元产品定义的唯一 Owner，拥有定位、价值、职责、盒子角色、垂类关系与产品边界。通用对象与运行机制由 [引元系统模型](../system/origin-system-model.md) 定义。

本项目以此定义为知识主线。[旧 AIOS 生态](../system/aios-ecosystem.md)仅作按需参考；涉及其他产品关系时重新核对，旧“AI 原生边缘枢纽”定位不再限制引元职责。INT AIOS 不再仅指陈展显示名称。

## 解决的问题与价值

设备连接之后，仍需要判断它们应在何时、为何、以何种方式共同工作。引元持续理解空间、人、设备与服务关系的变化，结合明确请求、长期规律、计划、实时状态和管理约束，围绕目标组织服务。

- 降低空间管理成本：承担持续观察、判断、协调与执行工作。
- 组织服务网络：将孤立设备与外部服务转化为可理解、可组合、可调度的能力资源。
- 让 AI 参与物理行动：从理解空间、判断介入到执行服务、验证结果，形成持续反馈。

核心目标是让 AI 成为持续存在于物理空间中的服务能力。

## 操作系统职责

这里的操作系统指面向物理空间的统一智能运行与资源组织体系。核心特征是持续运行、空间理解、主动判断和设备协同。

它统一描述对象和能力、维护空间状态，管理事件与任务生命周期，判断介入必要性，协调目标与资源冲突，约束权限，规划并调度设备和服务，验证结果并处理失败。

基础能力分为八项：设备与服务接入、能力抽象与注册、实时空间状态维护、长期记忆与规律学习、事件与异常识别、主动服务决策、任务规划与多设备协同、执行反馈与结果验证及闭环学习。详细机制引用系统模型，不以当前设备清单限定能力边界。

“操作系统”不自动构成自主研发底层内核、替代既有底层 OS 或全部智能本地运行的技术结论。

## 引元盒子的角色

引元盒子是引元在物理空间中的**常驻运行节点**，承担四类现场角色：

| 角色 | 职责 |
| --- | --- |
| 连接中心 | 连接设备、传感器、服务和其他资源 |
| 状态中心 | 持续维护空间状态 |
| 运行中心 | 承载事件、任务、判断和协同的持续运行 |
| 执行中心 | 将系统决策落实为设备与服务动作，并接收反馈 |

产品能力属于引元系统；盒子承载现场运行，不等于全部智能能力本身。节点硬件、底层软件、端云分工、多节点和离线能力需由后续技术方案与证据确定。康养当前形态由 [康养产品](origin-home-eldercare.md) 定义，不推广为所有场景的节点形态。

## 底座、垂类产品与具体场景

引元面向物理空间，可用于家庭、企业、工厂、园区、商业及公共空间等方向。这表示适用方向，不表示这些行业已经交付。

- **通用底座**提供统一对象模型与运行机制，支持能力组合、策略配置和资源扩展。
- **垂类产品**明确服务人群、长期价值、业务能力、流程及责任边界。允许开发专属业务能力，通过统一对象、能力描述和调用约束接入；场景差异不必全部压缩成参数配置。
- **具体服务场景**将空间、角色、资源、任务目标、业务流程、事件、权限、策略和交互组织为可验证的服务。
- **陈展样板**选取产品能力与场景进行体验表达；样板的设备、交互与模拟范围不决定底座或垂类产品的完整范围。

底层能力通用、对象模型稳定、能力可组合、策略可配置、场景可扩展，是持续演进原则；稳定模型允许有依据的扩展，不意味着对象集合永远封闭。

## 本项目与产品方向

[引元家庭康养产品](origin-home-eldercare.md)是引元的垂类落地，继续承载康养产品与具体服务场景设计。[陈展](aios-exhibition-context.md)是其中的样板表达。

既有资料中出现的引元盒子·教育版、家庭版、企业版保留为产品方向参考，不构成封闭产品线；当前可用状态、公开范围和交付情况仍未确认。

## 产品边界与证据

引元负责组织设备、能力与服务共同工作，不替代设备本身，也不以普通盒子、网关、设备管理后台、聊天或简单规则自动化概括其完整职责。

本文与系统模型描述产品定义和设计基线，不证明功能已实现、设备效果已验证或场景已交付。具体能力状态、运行条件、业务限制与验收证据由对应产品、场景或实现 Owner 记录。

其他产品的职责不在本文件推断；跨产品依赖按需核对旧生态及更新来源。
