# AIOS 家庭康养陈展：电视端设计系统与还原规范

本文件是 AIOS 家庭康养陈展电视端 Demo 的完整设计系统与还原规范 Owner。它统一拥有电视基础视觉、页面布局、通用组件、故事变体、特殊状态、例外处理、语音和动效、Mock 表达、Figma 还原、前端映射与验收标准。后续电视端新增、补充、复用、优化和调整均在本 Owner 原地更新。设备中心手机小程序使用独立的[手机设计系统](device-center-mobile-design-system.md)，不在本文维护。

本文件以 [陈展事实与边界](../knowledge/products/aios-exhibition-context.md) 为前提，服务于 [总体体验架构](../architecture/aios-exhibition-experience.md) 及 [四个体验故事 Owner](../architecture/exhibition-stories/README.md)。故事 Owner 拥有触发、证据、流程、主文案和分支结果；本文件拥有它们如何被设计、复用、变体化、还原和验收。

依据为事实文档中的来源 D、E、F、G、I、M。本 Owner 是当前 Demo 设计的唯一完整读取入口；“完整”表示所有已确认设计类型均有归属与路由，不表示真实设备已接入或独立前端组件库已发布。

## 2. Mock 与反馈表达

- 首轮数据、模型推断、设备动作及回执默认按模拟实现；依照用户明确要求，界面不添加演示标识，任何观众可见的标题、正文、列表、语音、反馈、记忆详情或状态文案都不得出现“Mock”“Demo Mock”等实现术语。Mock 只用于源代码命名／注释、Owner 能力边界和任务交付说明，不作为真实设备联调证据。
- 同一轮体验中的游客信息、体征、环境与设备运行状态应前后连续，不能切换页面就无缘由变化。
- 感知数据、分析结论、决策、执行反馈相互对应；模拟中的改善也要符合已确认的叙事和实际设备能力范围。
- 指令已发出、设备已执行、环境已有变化分别表达，不以一种状态代替另一种证据；无法确认时不能显示成功或改善。
- 模拟异常须在场景配置、测试记录和交付说明中明确标识，不能混入真实接入后的游客测量记录；该标识不进入观众可见界面。模型推断与测量值也应区分。
- 不预设统一生理阈值、异常判定标准或疗效承诺；具体数值、单位、范围与时序随首个相关页面形成可审阅的 Mock 基线。

## 3. 组件通用性与扩展

用户已确认需考虑后续设备加入；通用性以实际页面和基础 Figma 组件为起点。

- 已有 Figma 基础组件优先转为可复用前端组件；新的页面优先复用，确有差异再补充变体或新组件。
- 不将当前设备数量、设备名称、指标个数或某次示例数据写成视觉组件的固定边界。
- 说明正文默认允许自然换行；卡片按内容和规范内边距撑高或收缩，不能靠强制单行、裁切、缩小字号或改写文案适配。进度区应在正文后参与布局，不与多行文本抢占同一绝对定位区域。验收同时检查短文、长文和进度 100% 状态。
- 同类信息的来源设备、指标、单位、数值、可用状态、名称与素材应可配置；新增设备优先复用已有表达。
- 新设备带来新的交互或服务含义时，先判断是否需要新的组件状态或变体，不为了通用而强塞进不合适的模板。
- 感知、思考/分析等系统状态与具体页面组件的映射，由当前设计决定，不把业务状态写死为一组固定页面。

实现建议：将设备／Mock 数据、场景状态及视觉组件适当分离，便于后续替换数据源。当前工程基线见第 8 节，场景配置与复用入口见第 21.1 节；真实设备接口与状态驱动仍待接入设计。

### 动效与交互提炼原则

- 页面过渡先表达状态变化及前后元素关系，再确定时长。以自然连续、信息可跟随、节奏舒适为判断，不设全局统一的 3.4 秒或其他固定总时长。
- 每次转场按实际内容分配前置反馈、旧内容退场、共用组件形变、新内容进入和信息显现顺序；同时检查运动距离、并发数量、停顿及语音播报节奏，避免为了填满时长堆叠动画。
- 已验证的页面提亮、模糊淡出、同一外壳形变、卡片进入、进度反馈、语音球复位与展开等模式应提炼成可配置能力。复用的是交互意图和运动结构，具体参数随页面内容、距离和信息量调整。
- 逐页实现时，AI 主动识别新的组件、变体、状态、布局规则、交互模式和动效模式，判断应复用、扩展、拆分或优化，并把稳定结论更新到本 Owner；不等待用户逐项提醒。
- 可在已确认设计含义内直接优化适配性、连续性、可访问性、性能和代码复用。若优化会改变已确认文案、产品含义、主要视觉格局或体验路径，先说明依据、影响和建议，获得用户确认后再改。

## 5. 逐页协作与同步沉淀

**确认上一页并进入下一页，是主动沉淀的固定协作触发点。** 依据 2026-09-07 用户补充，此规则适用于感知，以及后续思考／分析、决策、执行、反馈的页面与流程；不需要用户再次提醒，也不把五类系统活动强制设计为五张独立页面。

进入下一页前，AI 先归纳已确认的上一页：

| 沉淀内容 | 归属 |
| --- | --- |
| 单故事的触发、证据、页面内容、进入／完成条件、前后衔接和分支结果 | 对应故事 Owner |
| 多故事共用状态、事件优先级、中断恢复和功能结构 | 总体体验架构 |
| 交互触发、反馈、等待、结果呈现、转场及语音配合 | 本设计规范对应页面／通用模式 |
| 组件职责、输入内容、变体、尺寸适配、使用边界、实现路径及验证范围 | 本设计规范组件条目 |
| 可复用部分、需要扩展的部分、发现的局限与优化建议 | 对应 Owner 原位更新，区分已确认、已实现和待优化 |

已有通用规则优先引用或修订，不为每页重复抄写；新页面开工先检查可复用模式，确有新含义再补充。保存的是当前有效规范，不是逐轮聊天记录。用户确认设计方向不等于确认所有代码细节；未验证实现不得标为已完成。涉及产品含义、文案或主要布局变化的优化仍先提出建议，获得确认后再执行。


1. 用户提供基础组件及当前页面的 Figma 节点；读取当前任务、事实 Owner、总体体验架构、对应故事 Owner 和本设计系统，只补充当前页面直接依赖。
2. 确认页面在正常路径中的作用，识别基础组件、系统状态、数据、文案和前后衔接。
3. 列出需要用户判断的文案建议、设计冲突或缺失信息；常规 Mock 数值和实现细节在已有授权内处理。
4. 主动检查当前页面是否产生可复用组件、变体、交互或动效，并评估已有模式是否需要调整；在页面实现任务绑定的范围内还原 Figma，将当前页接入正常路径，不擅自扩展未提供的页面。
5. 核验当前页面与受影响的衔接，包括动效是否自然、节奏是否舒适、组件是否能适应内容和设备数量变化；说明已完成内容和仍属模拟、未接入或未验证的部分。
6. 单故事流程与文案写入对应故事 Owner，共用编排写入总体体验架构，视觉、组件、交互与动效规范写入本文件，真实设备能力变化写入事实文档；按 `../RULES.md` 与 `../tasks/README.md` 处理任务及临时证据。

每轮只更新相关小节，不另建同一页面的平行总结、影子 PRD 或重复设计系统。文案或设计建议未经用户确认不得用“已确认”登记。

## 6. 验证尺度

**逐页核验**：与实际 Figma 的视觉和组件对应；当前页数据与文案一致；已实现状态、局部交互和前后衔接可用。目标电视尺寸、分辨率、输入方式在实际设计时确认，不能直接继承旧版验收参数。

**正常路径连通后**：核验游客是否可自助理解并完成；是否看懂持续感知、综合分析、决策、执行和反馈；正常状态下的主动空气优化是否有清楚动机和结果表达；已模拟能力是否可辨识。

单页还原通过不等于整条体验通过；Mock 流程通过不等于真实联调通过。验证聚焦本轮改动与实际剩余风险，不因规范扩展而重复无关检查。

### 语音动效（2026-09-04）

来源：用户指定 [React Bits Strands](https://www.reactbits.dev/animations/strands?glass=true&glassSize=0.6&scale=0.6&refraction=0.8&color1=f916f6&color2=1d8fff&color3=00daff&taper=2.1&thickness=1)。从官方注册表 `https://reactbits.dev/r/Strands-JS-CSS.json` 下载 JS/CSS 组件至 `src/components/strands/`，安装其 `ogl` 依赖；为当前 Vite JSX 配置补充 React 显式导入，另有 TypeScript 声明。

用户确认的两维状态：动作分默认、思考分析、语音播报；场景分正常、普通异常、紧急。动作以视觉波动频率、速度、振幅、光带数量／粗细、辉光和强度区分；场景分别使用原链接色、黄色系、红色系。二者可独立组合，不据此新增页面、异常判定规则或真实语音能力。

默认链接参数：glass=true、glassSize=0.6、scale=0.6、refraction=0.8、taper=2.1、thickness=1；正常配色 #f916f6 / #1d8fff / #00daff。其余沿用官方组件默认值。组件保留原右下角中心，160×160 透明画布中的玻璃球可见直径约 88px。

统一参数集中于 `VoicePresence.tsx`：

| 动作 | phase | 光带数 | speed | amplitude | waviness（视觉频率） | thickness | glow | intensity |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 默认待命 | idle | 3 | 0.42 | 0.8 | 0.85 | 0.85 | 2.2 | 0.45 |
| 思考分析 | thinking | 4 | 1.1 | 1.35 | 1.7 | 0.72 | 1.85 | 0.55 |
| 语音播报 | responding | 4 | 1.5 | 1.6 | 1.3 | 0.78 | 2.1 | 0.68 |

`idle` 用于没有主动交互、内部思考或播报的状态；`thinking` 用于思考／分析页和确认间 Loading，即使没有语音文字也持续呈现；`responding` 只用于主动提问或语音内容已进入播报阶段。语音框移动、缩放和播报前入场仍保持 `idle`，避免尚未播报时提前增强；播报、确认或思考结束后统一恢复 `idle`。动作状态只改变运动与光效，不改变蓝／黄／红语义色。

普通异常 severity=warning，配色为 #4a2100 / #7b2f62 / #c75500 / #ff7a00 / #ffad00 / #ffd34e / #ffe38a；紧急 severity=emergency，配色为 #46000e / #97132d / #e5183f / #ff3b42 / #ff6a54 / #ff9a73 / #b31964。黄色系以棕橙暗部、琥珀主色和暖黄高光为主，只加入少量低饱和梅红拉开层次；红色系以酒红暗部、鲜红与珊瑚主色、少量洋红过渡组成。两者必须保持黄／红主色语义，但不得退化为无明暗和色相层次的单色发光团。正常色板 #f916f6 / #1d8fff / #00daff 保持不变。

`thinking` 和 `responding` 的活跃差异主要由 speed、amplitude 和 waviness 表达；辉光、粗细和强度只负责增加可辨识的能量感，不得使光带边缘模糊、中心大面积过曝或影响色板层次。这组收敛后的动作参数同时适用于正常、普通异常和紧急三种语义色，正常状态只收敛晕光，不改变原蓝紫青色板。浏览器已核对三种语义色的思考与播报视觉；真实语音仍未接入。

语音球材质补充：用户要求暗系渐变和光影质感。玻璃合成层采用冷灰蓝到炭黑渐变、左上柔光与边缘阴影，主体不透明度约 0.88—0.98；保留既有折射、高光及球内 Strands 动效参数和色彩。修改仅位于 `Strands.jsx` 的玻璃 shader，球外仍透明。

### 新设备／能力接入规则

1. 先明确这次任务需要的感知内容、所属空间／人体组、来源设备与能力，以及结果字段和单位。能力依据读取事实 Owner；未核验部分继续按 Mock 边界处理。
2. 选择既有结果形态，配置参与设备与对应结果。一个设备有多项能力时按内容组织结果，不强制“一台设备只能有一页”；分页按结果内容数量生成。来源应可追溯，不能以模糊标题混淆设备输入与模型推断。
3. 复用卡片状态、进度、布局、轮播及溢出规则。同类设备扩展以数据配置为主；新的图表或交互形态需补充设计来源并扩展结果模板，不复制一套空间／人体卡片。
4. 沿用本节已经核定的间距、满格停留、单结果收缩与下一行淡化预览。设备增减后同步检查内容高度、分页和右侧整体可用空间；不能无限增长直到遮挡语音区。
5. 只有本次参与采集的来源影响该组完成条件。Mock 计时属于演示数据驱动方式，真实接入必须改用实际进度、有效结果与完成反馈，不能沿用“时间到了就成功”。

### 当前实现边界与后续优化

以下来自本轮代码核对，属于待实施优化，不能当作已经可用的能力：

- **优先分离采集驱动与显示**：当前卡片自己用计时器生成进度。后续由独立 Mock／真实适配层提供进度和结果，卡片只表达状态；满格后的 2 秒是展示停留，不是设备采集时间。
- **补齐任务与能力映射**：现有配置已有设备和结果，但没有独立能力标识及显式来源关联；视频结果还读取全局体验者与固定素材。后续将能力来源、图像及人物字段随结果传入，再支持其他设备或同类结果复用。
- **将编排参数化**：空间与人体是平级分类；当前代码把先空间后人体的展示和 Mock 启动绑定在页面中，尚未分离展示顺序与采集调度。复用到新的任务时，将参与组与启动条件传入编排层；并行、重试和再次采集需先确认产品规则。
- **完善内容驱动尺寸**：当前单结果按指标行数计算高度，仍依赖固定行高和两个可见指标行；不是任意长文案自适应。多行标签、不同字号和大量设备需要追加实际内容测量与可用空间策略，保留自然高度过渡。
- **按实际异常补分支**：缺失、失败、超时、取消等尚未实现；进入对应场景时先确认提示、继续条件和旧结果处理，再补模板，不能直接显示正常结果。

### 复用验收

每次扩展只验证受影响组合，至少覆盖新增设备数、结果数和内容长度：

- 当前任务未调用的设备不出现；人物、空间、来源与前后页面一致。
- 单设备完成不会提前结束整组；全部完成后完整停留 2 秒，再平滑转换；结果浏览不会重复触发完成通知或下一组。

- 标题到指标列表保持 24px；卡片上下留白、组间距离及分页不重叠，增加设备后不侵占其他区域。长文本超出当前模板时先适配再交付。
- 组件退出清理计时器；减少动态效果时信息仍可读。Mock 完成不能被描述为真实联调完成，感知结果不能被直接写成已执行的服务结论。

## 21. 空气环境异常分支与普通异常组件复用（2026-09-09）

- 进度组件的完成段跟随它所表达的对象与结果语义，不被页面级事件颜色笼统覆盖：正常为绿色，普通异常为 `#F4A600`，紧急为 `#FF3948`；轨道、尺寸、速度和进度计算不改变。空气异常在空间采集完成前保持正常色；结果呈现后，思考／分析与执行进度使用黄色。人体感知的心率、呼吸结果正常，其睡眠带采集进度保持绿色。反馈页如已确认恢复则回到正常色；未解决的事件反馈保持黄色；最终记录结束卡统一使用常规组件、绿色加载环与蓝色语音球，表示本轮记录结束而非健康恢复。
- 执行步骤的右侧状态列预留至少 `96px`，确保“指令已发送”“持续观察”等四至五字状态完整显示。当前正在处理的步骤使用事件语义色同步点亮状态点和状态文字：正常绿色、普通异常黄色、紧急红色；已完成步骤仍使用中性白色，不把步骤完成误解为事件已恢复。

- 当前空气异常故事不加入开窗／通风提醒，不新增窗户、新风或空调控制。若未来补充此类动作，必须先确认真实能力、用户操作与回执边界，再更新故事 Owner 和组件配置。

### 22.1 主动确认 `ConfirmationPanel`

### 22.2 确认转场与焦点

当前主体约 `700ms` 模糊退场，背景变暗到黑色 `50%`；顶部切换紧凑形态，弹窗在约 `700ms` 后由虚到实，语音球约 `1.1s` 起出现，问题与答案约 `1.6s` 起出现，总入场约 `2.6s`。稳定确认时不能重新露出静默待机或唤醒页内容。

两问间先用 `450ms` 将旧问题与选项模糊淡出；保留弹窗与单一球体，加载内容用 `450ms` 进入，加载阶段总计 `2s`，随后 `450ms` 淡出，再用 `500ms` 显示下一问，约 `600ms` 后可提交。加载文案沿用 Figma“收到，正在分析理解...”，字号和位置与原问题相同；白色点环沿用原 SVG `58×58px`，卡内 `(370,282)`，以 `1.8s linear infinite` 连续旋转，不显示截图标注框。弹窗与球体按传入等级同步蓝／黄／红；点环保持原稿白色，不表达事件等级。加载期间没有答案按钮，不代答、不重复提交；功能内页打开时暂停当前过渡，关闭后继续；重启／切换取消旧计时。减少动效偏好下不连续旋转，但保留加载文字。答案确定后约 `900ms` 退场，再复用 `3.4s` 分析入场。功能内页打开时隐藏确认弹窗、语音回原区域，关闭后回到未回答的问题。头像重启／切换清除旧答案和依赖计时，不能留下上一分支的反馈。

全屏设计画布使用不可滚动的裁切（当前 `.screen { overflow: clip }`），焦点移动使用 `preventScroll`；防止按钮聚焦使整个画布纵向偏移。画布仍按既有比例缩放，不改变正常页布局。减少动效偏好下缩短进出动画，保留问题、焦点和状态语义。

### 22.3 执行页的陪护变体

- `ExecutionPage` 保留右侧执行目标卡 `(1432,160)`、`428×182px` 基线；目标长文允许向下自适应。约 `1.6s` 后出现陪护过程卡，位置随目标卡高度顺延；默认 `(1432,362)`、`428×134px`，复用毛玻璃表面、`29px` 内边距、`28px` 标题图标和 `20px` 字号。
- 陪护环 `64×64px`，位于卡片右侧 `35px`、顶部 `35px`；复用结束卡底环和现有 SVG 进度构造，中心为 Figma 手心图标 `32×32px`。说明区不能侵占环形区域。
- `care.mode = timed` 是有限观察进度，故事时长由场景配置表达：5 分钟短时陪护压缩为 `12s`，15 分钟无回应观察压缩为 `20s`。环形进度只表示本轮观察窗口，不表示人体恢复率、安全评分或真实倒计时。`continuous` 是缓慢循环的不定进度，不设置恢复百分比或完成回调。两者复用同一卡片，运行点／环按事件使用黄色或红色，动作节奏不因紧急而加快闪烁。
- 顶部同时亮起感知与执行，语音球保持对应事件色，决策页口语告知按第 13.1 节接入，执行页继续收合，不重复展开播报。陪护结束与反馈条件由编排层决定，组件不能自行以时间判断身体恢复。
- 无回应观察期保持 `warning` 黄色。计时结束后必须由编排层读取预置结果：心率和呼吸数据恢复平稳时进入 `normal` 蓝色反馈；仍未恢复或出现进一步变化时转为 `emergency` 红色持续守护，并复用既有联系人同步卡，不新增升级页面体系。红色守护为未收束状态，不自动进入反馈、结束卡或记忆。

### 22.4 反馈、颜色与记忆配置

反馈组件允许 `chart = null`，无后续读数时取消图表并收缩卡片，不生成虚假恢复曲线。结束卡支持配置标题与说明；按用户最新截图确认，最终结束卡默认采用常规卡片、绿色加载环和蓝色语音球；此前事件反馈仍保留其实际异常语义，不能据此改写为已恢复。反馈指标通过独立 `tone` 标明单项异常：整行序号、字段、点和数值黄色／红色，正常呼吸等保留正常语义，不由卡片颜色一概覆盖。

身体故事沿用用户确认的反馈主标题。短时陪护反馈使用四行心率／呼吸当前值与前后对比，并复用趋势图；数值列预留 `140px`（无图的简短字段为 `110px`），不得裁切“118 → 86 次/分”。恢复卡片采用正常蓝色，语音在成长说明节点恢复正常色。

确认问题、分路决策、感知与反馈语音原文只读取[人体不适故事第 3–5 节](../architecture/exhibition-stories/body-discomfort.md#3-主动确认)，这里不维护第二份。长语音继续复用单向展开和 `24px` 安全区，不新增播报系统。

实现入口：`src/mock.ts` 的 `bodyQuestions`、`bodyStories`、`bodyHistory`；`src/main.tsx` 编排与本轮记忆释放；`ConfirmationPanel.tsx`、`ExecutionPage.tsx`、`FeedbackPage.tsx`、`VoiceDock.tsx` 和 `styles.css` 承载组件变体。无不适跳过执行、持续陪护禁止自动反馈；结果记忆只在对应反馈阶段提供，历史列表排除正常故事的本轮空气结果。

验收分别覆盖两问切换与不代答、三个显式回答分支与持续无回应分支、有限／不定进度、重启与回流清理、长文案和焦点不偏移、正常空间与呼吸的独立语义、单一可见交互语音球、反馈与记忆来源一致。无回应需分别验证“数据恢复平稳”与“仍异常并升级”：前者进入蓝色反馈、记录和正常回流；后者进入红色联系人同步与持续守护，下一步禁用且不生成成功反馈或记忆。真实设备、医疗判断、麦克风、真实十五分钟定时、联系人通知及外部介入回执不在本轮验收范围；升级路径不得显示联系人已确认、现场已接手或事件已解决。

- 头像浮窗“疑似跌倒”是 Demo 触发器。只有编排层已经确认当前空间有人时启用；启用后可从正常、空气异常、人体不适的感知、确认、思考／分析、决策、执行、反馈或功能内页触发。
- 触发时保存原故事、稳定页面、业务阶段、剩余停留时间、已获得回答和设备回执；停止原页面自动计时。恢复的是可理解的稳定状态，不复现被中断的动画帧。
- 抢占转场总计约 `600–700ms`：当前主体快速模糊淡出，背景加深，已展开语音先收合；紧急层随后进入。比普通 `3.2–3.4s` 页面转场更直接，但不得闪白、抖动、快速闪烁或播放警报声。
- 已打开的 `FeaturePanel` 立即隐藏并释放前景焦点；原页面不卸载业务上下文。正在显示的人体确认暂停，紧急确认成为唯一弹窗。
- 原流程已发出的设备指令和已收到的回执仍是事实，不能因 UI 抢占撤销或丢失；紧急分支可收束时由编排层重新判断是否恢复原流程。
- 只有“我没事”完成蓝色确认反馈和短期记录后恢复原流程。求助、两次无人回应或 Mock 通知已发出均保持紧急层，不自动回流。
- 紧急层不删除全局框架：品牌、Wi-Fi、日期天气、头像和底部主导航持续可见。底层页面在抢占期间不可操作，但不能用隐藏全局组件制造另一套页面外壳。

### 23.2 全局框架、顶部状态与页面亮度

- 顶部中心始终复用标准 `AiosStatus`：紧凑／展开形态、绿色状态点、字体、尺寸和页面中心轴均与其他故事一致，不使用红色顶部变体。持续感知保持点亮，并按当前页面同时点亮思考／分析、决策、执行或反馈。
- 确认阶段不增加“正在确认现场情况”或同类证据卡。射频疑似事件、空间、人在场和确认结果进入后续分析列表，不能在确认弹窗旁另造工作卡。
- 只有确认弹窗页面额外压暗；分析、决策、执行与反馈使用现有过程页 `30%` 黑色遮罩。紧急覆盖层本身保持透明，不能叠加第二层黑幕。
- 红色仅表达紧急事件内容：确认弹窗、结论／执行卡、状态环和语音球可使用 `emergency` 变体；全局框架不随事件等级重绘。

### 23.3 `ConfirmationPanel` 三按钮紧急变体

- 复用第 22.1 节的 `800×480px` 弹窗、问题区、单一 `VoiceDock` 和焦点机制；保留 `blur(20px)` 毛玻璃、圆角、描边和进出场，仅由 `severity = emergency` 将弹窗表面与语音球切换为红色。顶部状态仍使用第 23.2 节的通用样式。
- 页面问题和主动语音只从故事 Owner 读取，不在组件内复制。问题出现前保持背景压暗；问题、语音球和选项沿用“外壳先到、内容后到”的虚化入场。
- 三个答案按钮均为 `186×64px`，横向单行居中，间距 `24px`；总宽 `606px`，位于 `684px` 问题内容区内。文字 `20px / 500`，不得缩字号、裁字或换成图标。
- 焦点顺序固定为“我没事”→“我需要帮助”→“无人回应”；左右键或 Tab 移动，Enter 触发。焦点必须同时有轮廓、表面亮度和文字对比变化，不能只依赖红色。
- “无人回应”是展陈操作，不是体验者的语音回答。首次触发结束当前等待并进入再次询问；第二次触发才进入无回应分析。不得用真实超时、自动代答或一次点击跳过两次询问。
- 两次询问之间复用第 22.2 节 Loading、循环点环和防重复提交。无回应中间态不得使用暗示已收到本人回答的文案；具体 Loading 主文案留待跌倒页面逐页确认。
- 回答或无回应分支确定后，弹窗约 `900ms` 退场，再进入分析。提交后锁定按钮，切换、重启或抢占取消所有旧计时和焦点。

### 23.4 分析、决策与语音生命周期

- 分析页复用第 12 节结构，事件语义保持红色；右下角只显示红色 `thinking` 语音球，不展开、不播报。列表只呈现射频疑似事件、人在场与空间上下文、本人回答或无回应、当前协同路径，不生成伤情或医学结论。
- 决策页复用第 13 节自适应结论卡与三行窗口，卡片使用紧急红黑渐变。长文自然换行并撑高；右侧状态环、进度和当前项统一为红色。
- 决策结论完整出现后，按故事 Owner 对应分支展开口语告知。只有语音内容完整展示后才能自动进入执行或反馈；不得用卡片文字机械截断成语音。
- “我没事”回答被接受后，后续确认反馈、决策和记录切换为 `normal` 蓝色，表示本轮确认结果；不得写成设备成功、误报结论或健康诊断。
- 求助与无人回应分支在决策、联系人同步和持续守护全过程保持红色。执行状态语音只有在相应 Mock 动作发生后才能说“正在同步”或“已同步”。

### 23.5 执行、联系人同步与持续守护

- 执行页复用 `ExecutionPage` 和第 22.3 节的陪护变体。左侧只保留场景加载、主标题和游客身份，不增加协同卡；全局页头与底部导航保持可见。
- 右侧按最终确认顺序排列三卡：执行目标 `428×182px` → 同步紧急联系人 `428×134px` → 正在持续守护 `428×134px`；卡间均为 `20px`。执行目标读取故事 Owner，不在组件内复制。
- 联系人卡使用 `pending / running / complete` 视觉状态，对应“准备通知／正在通知／通知已发出，等待现场介入”。运行时红色环循环，完成时红色圆环走满并保留同步图标；不得切换为勾或把圆环 100% 解释为联系人确认。
- 守护卡使用红色不定环持续运行，说明“持续守护，记录实时状态”。不显示完成百分比，不表达救援进度、人员状态或等待时限。
- 编排状态收敛为 `pending → initiated → guarding`；求助和无人回应不再增加手动“升级协同”页面或左侧步骤卡。Mock 通知完成后继续守护，不自动进入反馈、结束卡、成功记忆或默认故事。
- 状态模型禁止预置 `acknowledged`、`handedOff`、`resolved` 或同义成功状态。没有外部回执时，不能显示联系人已确认、现场人员已接手、事件已解决或执行成功。重启和故事切换只是 Demo 控制，不等于解除事件。

### 23.6 “我没事”反馈、记忆与原流程恢复

- 本分支使用 `FeedbackPage` 的蓝色确认结果变体，可不显示趋势图。结果只包含本人已回应、当前不需要帮助、未发起协同和本轮确认结束；不展示身体恢复曲线或设备执行成功。
- 反馈完成后形成一条短期“新发现”，记录疑似事件、本人回答和未发起协同，不写“射频误报”。随后回到抢占前的故事与稳定页面，恢复剩余计时。
- 若原流程在抢占期间产生了新的设备回执，恢复时先用当前状态合并，不倒退到旧状态。此条是编排一致性要求，不代表真实后台并发已经实现。
- 回到原流程时 `VoiceDock` 恢复原故事的动作和语义；紧急确认层、答案、两次无回应计数和临时记忆必须清理。

### 23.8 动效、可访问性与验收

- 紧急进入必须在人在场后的正常、空气异常和人体不适至少各选一个稳定页面验证；另验证功能内页打开、语音展开和主动确认进行中三种覆盖状态。
- 验证原计时暂停、完整全局页头与主导航、通用顶部状态、单一红色毛玻璃弹窗、单一活动语音球、背景内容不可操作，以及“我没事”后焦点和剩余计时正确恢复。
- 验证三按钮单行完整显示、两次无回应不能一步跳过、确认页无额外证据卡、非确认页不叠加黑幕、分析静默、决策语音完整、执行三卡顺序、联系人圆环完成后不出现勾、持续守护不自动完成或回流。
- 跌倒中的头像浮窗必须保留重新开始、上一步、下一步和三个异常故事入口。只在确认未回答、页面转场、持续守护不得伪造完成等必要节点禁用跳步；不能因进入紧急故事删减 Demo 查验能力。
- 验证“我没事”分支只形成确认记录，不出现误报、健康正常、设备成功或协同成功；求助与无人回应不生成成功记忆。
- `prefers-reduced-motion` 下缩短抢占和页面进出、停止连续旋转，但保留红色内容层级、标准顶部状态、状态文字、焦点和所有操作结果；不能因减少动效跳过再次询问或执行状态。
