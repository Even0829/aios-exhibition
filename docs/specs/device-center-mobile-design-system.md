# 设备中心手机小程序设计系统

> 状态：概念方向评审中
> Owner：设备中心手机小程序的视觉、组件、交互、动效与页面还原规范
> 产品范围与业务规则读取：[设备中心 PRD](device-center-prd.md)

本文只维护手机小程序设计。电视端陈展视觉与还原规则由[电视端陈展设计系统与还原规范](aios-exhibition-design-system.md)维护。执行手机任务只读取本文及相关产品需求；执行电视任务不加载本文，除非任务明确涉及跨端一致性。


## 1. 设计方向

- 采用 Apple 家庭类产品常见的安静、清晰、直接和系统化体验，优先使用浅色界面、充足留白和清楚的信息层级。
- 页面主背景使用柔和浅灰，主要内容表面使用白色；通过间距、字号和分组建立层级，阴影与描边保持克制。
- 品牌蓝用于主操作与选中状态；绿色表示在线或成功，橙色表示待处理，红色只用于错误、危险和破坏性操作。连接状态不能只用颜色表达。
- 电视端与手机端通过品牌强调色、设备图片、状态语义、名称和空间结构保持一致，不复制电视的大面积深色玻璃面板。
- “Apple 风格”只作为设计语言，不直接复制 Apple 商标、完整页面或未授权的 SF Symbols 素材。图标应使用合法授权、风格一致的线性／填充体系。

## 2. 字体、布局与表面

- 使用系统字体栈，iOS 优先系统字体，其他平台使用字形与字重接近的合法回退字体；中文正文保持清晰，不以极细字重营造质感。
- 页面使用“大标题／分组标题／正文与辅助信息”三级层级。大标题可随滚动收合为紧凑导航栏，但不得造成内容跳动。
- 采用 `8px` 基础间距节奏；页面横向安全边距建议 `16–20px`，分组间距大于组内行距。
- 卡片、按钮和弹层采用连续圆角。设备卡可使用 `16–20px` 圆角，分组列表以系统式行结构为主；消息列表不得为了视觉丰富拆成多种卡片。
- 毛玻璃只用于底部标签栏、顶部悬浮导航和模态弹层；普通设备卡、消息行和设置行使用稳定实色表面。
- 适配安全区域、动态文字和长中文名称；关键状态、时间和数值不得因字体放大被裁切。

## 3. 共用组件

| 组件 | 规则 |
| --- | --- |
| 大标题导航 | 标题、返回和必要右侧操作；滚动时可收合，返回路径保持稳定 |
| 底部标签栏 | 固定“首页／助手／消息／我的”四项；首页首期以设备为主要内容，选中态同时使用图形和文字，不只变色 |
| 设备卡 | 设备图片或图标、名称、空间、连接状态和一个关键状态；控制复杂度进入详情 |
| 分组列表行 | 用于消息、设置、账号、成员和空间；行高不小于 `52px`，点击区域不小于 `44×44px` |
| 开关与滑杆 | 使用接近系统控件的尺寸和反馈；滑杆同时显示名称、当前值和单位 |
| 单选／多选列表 | 空间选择使用单选，多设备管理使用多选；当前选择和禁用原因必须清晰 |
| 空间管理行 | 显示空间名称、设备数量和排序把手；编辑状态提供重命名、调整设备和删除入口 |
| 底部操作面板 | 用于空间选择、筛选、普通操作和步骤说明；支持下滑关闭时仍提供明确关闭按钮 |
| Demo 悬浮球 | 仅 Demo 模式显示；固定在右下安全区内、底部标签栏上方，点击打开“演示状态”底部面板，不承载正式业务提醒 |
| 演示状态面板 | 单选预设情境、当前情境说明、角色切换和“恢复默认”；不提供会产生冲突的任意异常开关组合 |
| 系统确认框 | 仅用于解除账号、移除设备、删除空间等高影响操作；文案说明具体影响 |
| 状态反馈 | 使用行内处理中、结果文字和必要进度；不连续弹出 Toast 代替控制结果 |
| 空状态与骨架 | 保留一个主操作；加载骨架不伪装成真实设备状态 |

## 4. 页面交互

- 页面推进和返回保持方向一致；从设备卡进入详情时保留来源位置，返回恢复原滚动位置和筛选条件。
- 首页首期以设备为主要内容，但页面命名、顶部结构和内容间距允许后续增加已确认的家庭概览模块；当前不得展示无业务内容的占位卡片。
- 设备控制先提供按压反馈，再进入“处理中”；只有真实回执成功后更新最终状态。失败或超时在原控件附近说明，不只显示全局提示。
- 空间管理从“我的 → 家庭与空间”进入：列表显示名称、设备数量和顺序；右上“添加”进入空间命名页，创建后询问是否立即安置设备。
- 空间详情按“空间名称 → 设备列表 → 编辑操作”排列。重命名使用独立表单；排序在编辑状态显示拖动把手，同时保留可访问的上移／下移操作。
- 删除空空间使用系统确认框；空间内有设备时先进入迁移页，选择目标空间或“未分配”，迁移完成后再删除。删除按钮不能与普通保存并列为同等主操作。
- 空间调整支持单设备修改、多设备不同目标空间的一次编辑，以及多选设备批量移动到同一空间。首期使用列表选择与统一保存，不把拖拽作为唯一交互。
- 消息页只使用一个列表，每项显示未读圆点、标题、一行摘要和时间。点击后进入详情或关联处理页；后台分类、级别和对象不作为前台导航。
- 涂鸦同手机流程中，全屏二维码页先突出“保存二维码”，成功后分步提示前往涂鸦 App 并从相册识别；只有官方深链与微信平台能力都验证通过后才显示“保存并打开涂鸦 App”。回到小程序后保持原任务并自动检查结果。
- 添加设备流程将“设备接入成功”和“设备添加完成”分开表达。接入后必须选择已有空间或新增空间；新增成功后返回流程并自动选中。中途退出时以“待完成配置”恢复，不把未配置设备混入正常首页。
- Demo 悬浮球位于右下方，视觉直径建议 `48–52px`，距页面右侧安全边距 `16px`，与底部标签栏可视边缘至少留 `12px`。键盘、系统面板或页面主要按钮占用该区域时平滑上移，不遮挡添加设备、保存或设备控制。
- 点击悬浮球打开半高底部面板；当前情境使用单选状态和简短说明表达，主情境一次只选一个，角色切换独立呈现。关闭后悬浮球保留轻量当前状态标记，但不持续动画。
- Demo 入口及面板使用“演示状态”“恢复默认”等文案，不出现“Mock”“调试”或 Home Assistant。正式家庭版本不渲染该组件，也不保留空白占位。

## 5. 动效与触觉反馈

- 按钮、选择和状态切换建议 `180–240ms`；页面推进、返回和底部操作面板建议 `260–360ms`。
- 悬浮球出现、上移和面板展开沿用上述节奏；允许轻微缩放和弹簧感，不使用呼吸灯、无限旋转或持续漂浮吸引注意。
- 使用轻微弹簧式缓动表达直接操控，避免大幅缩放、过度回弹、长时间模糊和装饰性连续动画。
- 设备卡进入详情可使用轻量共享元素或位置连续感；没有可靠实现条件时使用标准水平推进，不以复杂转场阻塞功能。
- 系统允许时，为选择、控制成功和错误提供不同强度的轻触觉反馈；触觉只是补充，关闭后不影响状态理解。
- 遵循系统“减少动态效果”：缩短或取消大幅位移、共享元素和持续动画，保留焦点、进度、处理中和最终结果。

## 6. 可访问性与验收

- 所有操作区域不小于 `44×44px`；文本和关键图标满足清晰对比，状态使用文字与视觉标识共同表达。
- 支持系统字体放大后的主要页面、设备名称、数值单位、消息摘要和按钮文案；不得只靠固定高度裁切。
- 开关、滑杆、单选和多选拥有明确名称、当前值和禁用原因；颜色、位置或触觉均不能作为唯一反馈。
- 验收覆盖浅色表面层级、四项标签栏、设备卡与详情、空间批量调整、单一消息列表、账号接入步骤、二维码保存与返回恢复、Demo 悬浮球及演示状态面板、减少动态效果和常见手机安全区域。
- 当前基线不等于最终视觉稿；具体颜色值、字号、圆角、图标、页面布局和暗色适配在手机视觉设计阶段确认后补充。

## 7. 首页概念方向评审

前端 Demo 实现前先评审三种首页概念，评审材料位于 [`.tmp/reviews/device-mobile-home-concepts/README.md`](../../.tmp/reviews/device-mobile-home-concepts/README.md)。三种方向使用同一产品内容：我的家、8 台在线／4 台离线、家庭连接正常、全部／客厅／卧室、四台代表设备，以及首页／助手／消息／我的四个入口；灯、窗帘和传感器严格按各自能力展示。现有概念图底部旧文案“设备”需在下一轮视觉稿统一改为“首页”。

| 方向 | 核心表达 | 适用判断 |
| --- | --- | --- |
| A 系统家居卡片 | 两列设备卡，平衡设备图片、状态与快速控制 | 适合作为日常首页基础方向 |
| B 空间概览 | 更强空间图片与家庭氛围，重点设备视觉突出 | 适合空间详情或重点展示，设备多时效率较低 |
| C 设备清单 | 系统列表行，状态和值集中呈现 | 扩展性和信息效率最好，氛围感较弱 |

当前建议以 A 为首页基础，吸收 C 在设备量增大时的列表能力；B 的空间图像语言可用于空间详情或空状态。最终方向以用户评审为准，未确认前不沉淀具体首页尺寸，也不进入前端 Demo 实现。
