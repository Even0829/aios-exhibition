## 2. 产品目标

设备中心通过 Home Assistant 统一承接不同品牌设备与服务能力，并以自有产品界面向家庭用户提供设备查看、状态理解和控制。用户不需要知道或直接操作 Home Assistant。

首期形成两个交互端：

- **电视端**：面向家庭现场，负责设备展示、基础手动控制、语音控制和手机接续引导。
- **手机小程序**：首期只服务设备中心，负责账号与设备的添加、授权、配置、管理、完整控制、家庭外远程控制、消息和 AI 对话控制。

### 2.1 产品原则

1. **统一体验**：不同品牌通过一致的设备、能力和状态语言呈现，品牌差异只在必要处出现。
2. **能力驱动**：页面根据设备实际能力展示控制项，不按设备名称硬编码。
3. **状态可信**：连接、工作、授权、指令和更新时间分别表达；未收到成功回执时不得显示成功。
4. **跨端闭环**：电视无法完成的添加、授权和复杂配置，应明确接续到对应的小程序任务，并同步最终结果。
5. **支持扩展**：品牌、账号、设备类型、设备数量和能力均不可按当前 Demo 固定。
6. **最少操作**：电视优先完成查看与高频轻控制；复杂操作进入小程序。

## 5. 共用业务对象

| 对象 | 产品含义 | 扩展要求 |
| --- | --- | --- |
| 家庭 | 账号、空间、设备和成员的归属边界 | 不假设一个用户永远只有一个家庭 |
| 家庭成员 | 家庭管理员或普通成员 | 首期两级角色，数据关系需支持未来增加只读、临时和细粒度权限 |
| 空间 | 客厅、卧室等设备所在位置，用于组织、展示和空间级控制 | 空间可新增、重命名、排序和删除；未分配设备有独立系统分组 |
| 接入来源 | 可连接设备或服务的品牌／平台类型，如 Xiaomi Home、Tuya | 对应 Home Assistant 的集成类型；来源数量可扩展 |
| 接入连接 | 某个来源下已完成配置的一次连接；当前云端来源在用户界面中表现为“小米账号／涂鸦账号” | 同一来源可建立多个连接；未来也可表示本地发现、网关等非账号型连接 |
| 设备 | 用户理解的一台物理设备或服务设备 | 设备类型和数量可扩展，并保持稳定身份 |
| 设备能力 | 设备可提供的状态或操作，如开关、亮度、色温、窗帘开合、温湿度 | 一台设备可有多个能力；能力分为只读和可控制 |
| 设备状态 | 连接、工作状态、指标值和最近更新时间 | 必须标明是否为实时、缓存或未知 |
| 设备配置状态 | 设备接入后的配置进度，如待配置、已完成 | 接入成功不等于添加完成；未完成名称与空间配置的设备不得作为正常设备展示 |
| 控制指令 | 用户发起的一次控制请求 | 必须记录目标、发起端、过程和最终结果 |
| 手机接续任务 | 电视发起、由小程序完成的添加、授权或设置任务 | 必须关联任务类型、家庭、目标对象、有效状态和结果 |
| 消息 | 由设备、接入连接、控制任务或系统产生、需要用户知晓或处理的事项 | 需包含接收人、级别、状态、关联对象、处理入口和结果 |
| AI 会话 | 用户以自然语言查询或控制家庭空间与设备的一次连续交互 | 必须受家庭权限、设备能力和控制回执约束 |

### 5.1 对象关系规则

- 一个家庭可以有多个空间、成员、接入来源、接入连接和设备。
- 一个接入来源可以建立多个连接；一个连接可以关联多台设备。
- 一台添加完成的设备至少属于一个家庭、一个有效来源连接和一个主要空间；“未分配”只承接历史、异常或待完成配置数据。
- 接入连接与空间是相互独立的关系：连接说明设备来源，空间说明家庭位置；更换空间不得改变设备的来源账号、稳定身份或能力。
- 一台设备可以同时具有多个能力。前端只展示当前已确认并允许使用的能力。
- Home Assistant 的多个底层实体可在产品侧归并为一台用户设备；底层实体名称不直接展示给用户。
- Home Assistant 的集成用于连接品牌或平台；设备是一个或多个实体的逻辑组合；实体状态与可执行动作需要映射为产品可理解的设备能力。
- 设备重新授权或重新连接后应保持原有设备身份、空间和用户配置；无法可靠识别时不得自动错误合并。

### 5.2 品牌账号、设备与空间的管理边界

| 对象 | 决定什么 | 可管理内容 | 不应连带改变 |
| --- | --- | --- | --- |
| 品牌账号／接入连接 | 设备从哪里发现、授权和同步 | 绑定、命名、重新授权、同步、解除 | 不因账号重命名或重新授权改变设备空间、产品名称和稳定身份 |
| 设备 | 家庭里具体是哪一台设备、有哪些能力 | 添加、产品名称、空间、可见范围、移除 | 移除产品设备不删除原厂 App 中的物理设备，也不删除账号或空间 |
| 空间 | 设备在当前家庭中的主要位置 | 新增、重命名、排序、删除、移动设备 | 移动设备不改变来源账号、稳定身份和设备能力 |

关系与生命周期规则：

1. 品牌账号形成的接入连接归当前家庭管理，不归执行绑定的某个成员私有。一个家庭可有多个来源和连接；同一品牌也可绑定多个账号，账号名称必须可区分，只有家庭管理员可管理。
2. 一台已添加设备首期只关联一个有效来源连接和一个主要空间。来源连接用于同步，主要空间用于展示、权限和空间控制。
3. 账号授权失效或暂时断连时，保留关联设备、产品名称和空间，只将设备标记为不可同步或不可控；重新授权成功后按稳定标识恢复原关系。
4. 解除账号前必须列出受影响设备和数量。确认解除后停止这些设备的同步与控制，并从正常设备范围移除；不删除原厂 App 中的设备，也不删除家庭空间。若用户取消，原关系不变。
5. 从设备中心移除单台设备，只移除该设备在本产品中的关系和控制入口；账号连接、同账号其他设备、空间及原厂设备不受影响。
6. 删除空间前必须迁移其中设备；删除账号或设备不自动删除任何空间。
7. 同一设备被多个连接发现时，系统依据稳定标识提示“已添加”或“可能重复”，不得静默生成两个可控设备，也不得在证据不足时自动合并。
8. 设备来源账号不能在设备设置中直接切换。更换来源需明确说明影响，移除原关系后从目标账号重新接入；若能验证为同一物理设备，可在重新接入时恢复原名称和空间。
9. 移除单台设备后，后续账号同步可再次将其显示为“可添加”，但不得自动恢复；重新绑定同一账号并确认同一设备时，可提示恢复原名称和空间，由管理员确认。

## 6. 状态模型

### 6.1 连接状态

| 状态 | 含义 | 展示与操作 |
| --- | --- | --- |
| 在线 | 当前可以获取状态，且具备条件时可控制 | 展示实时状态，允许已授权控制 |
| 离线 | 当前无法与设备通信 | 禁止控制；如有缓存，明确显示“上次状态”和更新时间 |
| 状态未知 | 暂时无法判断是否在线 | 不推断工作状态；提示稍后查询 |

### 6.2 工作状态

- 工作状态描述设备功能是否正在运行，例如已开启、已关闭、窗帘开合 50%。
- 在线与开启是两个维度：设备可以“在线且关闭”，也可以“离线但上次状态为开启”。
- 无开关能力的设备不显示开启／关闭控件，例如温湿度传感器只显示读数。

### 6.3 授权状态

| 状态 | 电视表现 |
| --- | --- |
| 已授权 | 正常展示账号和设备 |
| 授权失效 | 展示需要重新授权；相关设备禁止控制；引导手机处理 |
| 连接异常 | 说明当前无法同步，保留已确认的缓存信息 |

后续可新增授权中、解除中等过程状态，但不得将过程状态显示为成功。

### 6.4 指令状态

控制指令遵循“用户发起 → 校验设备与权限 → 指令处理中 → 收到执行结果 → 更新状态或说明失败”的闭环。

| 状态 | 产品行为 |
| --- | --- |
| 处理中 | 显示正在执行，避免重复提交同一操作 |
| 成功 | 使用设备回执更新工作状态和更新时间 |
| 失败 | 保留上次确认状态，说明失败并允许重试 |
| 超时／结果未知 | 保留上次确认状态，提示结果尚未确认，可稍后查询 |

### 6.5 数据更新时间

- 所有设备状态需保留最近一次确认时间。
- 实时状态、缓存状态和未知状态必须可区分。
- 电视重新打开、手机完成配置或设备状态变化后，应获取并展示最新可用状态。

### 6.6 设备配置状态

| 状态 | 含义 | 展示与操作 |
| --- | --- | --- |
| 待完成配置 | 设备已接入，但名称或空间尚未保存 | 仅管理员可在待处理入口继续配置或放弃；不得进入正常设备列表、电视展示和 AI 控制范围 |
| 已完成 | 名称、空间和必要关系已保存 | 按权限进入首页、电视端、消息和 AI 上下文 |

管理员放弃待完成配置时，只移除本产品中的待配置关系，不删除原厂 App 中的设备；后续同步仍可重新选择添加。

## 9. 电视与手机小程序接续

| --- | --- |
| XD-001 | 二维码必须指向明确的小程序任务，而不是统一首页。 |
| XD-002 | 任务需关联当前家庭、任务类型和目标账号或设备；不在二维码文案中暴露敏感凭据。 |
| XD-003 | 二维码具有有效状态；过期后明确提示重新发起。 |
| XD-004 | 手机扫码后，电视显示已接续或请在手机继续，不冒充任务完成。 |
| XD-005 | 手机任务完成后，电视重新获取账号、设备和状态，并展示最终结果。 |
| XD-006 | 手机取消、失败或超时后，电视保留原数据并允许重新发起。 |
| XD-007 | 从接续页返回时，恢复到发起任务的设备、账号或列表位置。 |

当前 Demo 二维码仅为布局占位，不代表上述真实接续能力已经实现。

## 10. 异常与降级规则

| 场景 | 电视展示 | 是否允许控制 | 后续操作 |
| --- | --- | --- | --- |
| 设备离线 | 离线；可显示带时间的上次状态 | 否 | 等待恢复或去手机检查 |
| 状态未知 | 状态暂未确认 | 否 | 稍后查询 |
| 账号授权失效 | 需要重新授权 | 否 | 手机重新授权 |
| 家庭主机连接中断 | 当前显示上次获取状态 | 否 | 等待连接恢复 |
| 控制失败 | 说明失败，保留旧状态 | 可重试 | 用户再次发起 |
| 控制超时 | 结果尚未确认，保留旧状态 | 谨慎限制重复操作 | 稍后查询 |
| 二维码过期 | 二维码已过期 | 不适用 | 返回并重新发起 |
| 手机任务失败 | 配置未完成，原数据不变 | 不适用 | 返回并重新发起 |

## 11. 跨端一致性要求

- 电视和手机小程序展示同一设备身份、空间、账号归属和最新确认状态。
- 任一端成功控制后，其他端应在下一次同步时获得新状态。
- 账号授权变化应同步影响相关设备的可控状态。
- 设备重命名、换房间、添加、移除或重新授权完成后，电视列表与详情应更新。
- 不同端对同一设备发出冲突指令时，最终展示以设备确认结果为准，不以某一端的本地按钮状态为准。
- 用户可见文案不出现 Home Assistant 的名称、后台概念或原始实体标识。
- 消息、AI 和手动控制读取同一家庭、权限、设备能力和最终确认状态。

## 12. 数据与操作记录要求

后端需支持产品判断所需的信息，但本 PRD 不限定数据库和接口形式：

- 家庭、成员、空间、接入来源、接入连接、设备及能力之间的关系。
- 设备连接状态、工作状态、指标值、状态来源和最近确认时间。
- 账号授权状态及其影响范围。
- 控制指令的发起端、目标、内容、处理状态和最终结果。
- 手机接续任务的类型、目标、有效状态和结果。
- 消息的类型、级别、接收人、关联对象、未读与处理状态。
- AI 会话的家庭上下文、设备指向、澄清、确认和控制结果；聊天内容保存范围需服从后续隐私规则。
- 关键失败原因应能支持用户提示和问题排查，但不直接向用户展示内部错误信息。

## 13. 验收标准

### 13.1 通用扩展性

- 新增一个品牌账号时，不需要修改“只能是小米／涂鸦”的固定页面逻辑。
- 新增一种设备能力时，可按能力决定只读展示或可控组件。
- 新增一种接入来源时，可沿用统一接入外壳并补充该来源自己的授权步骤，不修改既有来源流程。
- 设备和账号数量增加后，列表、计数和空间筛选仍基于实际数据工作。
- 无法识别的能力不展示错误控件，也不影响设备其他已支持能力。

### 13.2 电视端闭环

1. 用户可以从设备列表进入详情并返回原设备位置。
2. 在线设备可完成一次开关或数值调节，并以成功回执更新状态。
3. 离线、未知或授权失效设备不能被误控制。
4. 控制失败和超时不会覆盖上次确认状态。
5. 语音指向不明确时先澄清，批量操作先确认。
6. 添加设备、添加账号、账号管理、重新授权和设备设置均可进入对应手机接续页。
7. 手机接续返回时恢复来源位置；任务完成后可同步新结果。
8. 无设备时没有重复添加按钮和不可执行语音示例。
9. 返回键每次只退一层；紧急事件可以抢占设备中心。

### 13.3 当前未完成的真实能力

以下项目必须在开发计划中单独验证，不能以 Demo 通过代替：

- Home Assistant 的部署与稳定连接。
- 小米、涂鸦及其他品牌的真实授权、设备发现和能力映射。
- 可扫描的小程序二维码和任务接续。
- 家庭外远程控制、安全授权和状态同步。
- 真实设备指令回执、失败原因和超时策略。

## 15. 手机小程序信息架构

首期底部使用四个入口：

1. **首页**：首期以家庭与空间切换、设备列表、设备详情和添加设备为主体；命名为首页，为后续已确认的家庭概览能力保留扩展位置。
2. **助手**：以文字聊天查询、控制家庭空间和设备。
3. **消息**：查看设备、接入连接和系统事项，进入对应处理流程。
4. **我的**：家庭与空间、成员、接入账号、设备管理、通知设置和帮助。

四个入口分别承接家庭高频入口、AI 交互、待处理事项和低频管理。首期首页不展示尚未确认的空模块，设备仍是页面主要内容；接入账号不单独占用底部入口，避免品牌管理与日常控制同级。

## 16. 手机小程序通用需求

| 编号 | 需求 |
| --- | --- |
| MP-001 | 首次进入需完成小程序身份登录；已有家庭直接进入首页，无家庭时进入创建或加入家庭。 |
| MP-002 | 一个用户可加入多个家庭；切换家庭后设备、空间、消息、AI 上下文和权限全部随之切换。 |
| MP-003 | 首期角色为家庭管理员和家庭成员。管理员可管理账号、设备、空间和成员；成员只查看和控制已授权设备。 |
| MP-004 | 首页显示当前家庭、家庭连接状态、空间筛选、设备列表和添加设备入口；首期设备内容保持主导，不展示未确认的占位模块。 |
| MP-005 | 设备按在线优先展示；卡片显示名称、空间、连接状态和关键工作状态。 |
| MP-006 | 设备详情根据实际能力展示开关、程度数值、模式或只读指标；没有对应能力时不展示。 |
| MP-007 | 手机控制与电视控制使用同一权限、状态、指令和回执规则。 |
| MP-008 | 管理员可在设备设置中修改单台设备的名称、空间和可见范围，或移除设备；移除前说明影响并确认。 |
| MP-009 | 家庭外控制使用同一设备页面，不另设“远程设备”列表；不可控时说明是主机、设备、授权还是权限原因。 |
| MP-010 | 控制结果在重新进入小程序后仍能查询，不因页面关闭而丢失最终状态。 |
| MP-011 | 管理员可在“我的 → 家庭与空间 → 空间管理”中连续调整多台设备的空间并一次保存，也可多选设备批量移动到同一空间；成员不能修改。 |
| MP-012 | 空间调整成功后同步影响设备列表、详情、AI 空间语义和电视端；部分失败时逐台返回结果并保留失败项原空间。 |
| MP-013 | “添加设备”必须先选择已有接入账号或完成新账号绑定；设备接入后必须选择已有空间或新增空间，保存名称与空间后才算添加完成。 |
| MP-014 | 设备接入成功后退出配置时，设备进入“待完成配置”；管理员可从首页提示、设备管理或消息继续完成，未完成前不得作为正常设备进入首页、电视端和 AI 控制范围。 |

### 16.1 家庭与成员

- 创建家庭时至少填写家庭名称，空间可先使用默认项再调整。
- 管理员以邀请方式添加成员；邀请需绑定家庭、角色和有效状态。
- 成员被移除后，立即失去该家庭的远程查看和控制权限。
- 数据关系需允许未来增加只读成员、临时成员和按空间或设备授权，首期不提供对应复杂界面。

### 16.2 空间管理与设备安置

| 编号 | 需求 |
| --- | --- |
| SP-001 | “我的 → 家庭与空间 → 空间管理”展示当前家庭的空间列表、设备数量和排序；客厅、卧室只是样本，不是固定上限。 |
| SP-002 | 管理员可新增空间；同一家庭内空间名称不可重复。创建成功后可立即选择设备安置，也可稍后处理。 |
| SP-003 | 管理员可重命名空间；新名称同步到首页筛选、设备详情、电视端和 AI 空间语义，不改变空间内设备身份。 |
| SP-004 | 管理员可调整空间顺序；顺序同步影响首页空间筛选、空间管理页和电视端的空间展示。 |
| SP-005 | 删除空空间时说明影响并确认；删除包含设备的空间前，必须先选择其他空间或“未分配”作为迁移目标，全部迁移保存成功后才删除。 |
| SP-006 | “未分配”是系统分组，只用于历史数据、异常导入或添加流程中断后的待配置设备；管理员不能删除或重命名，正常添加流程不得把它作为主动选择。 |
| SP-007 | 设备接入成功后必须逐台选择已有空间或新增空间；多台设备可批量放入同一空间，也可分别选择。新增空间成功后返回原添加流程并自动选中该空间。 |
| SP-008 | 设备详情的“设备设置”允许修改单台设备空间；空间管理允许多台设备分别调整目标空间后一次保存。 |
| SP-009 | 批量选择多台设备时可统一移动到同一空间；不同目标空间使用逐台调整后统一保存，不以拖拽作为唯一操作。 |
| SP-010 | 空间调整不改变设备的来源账号、接入连接、稳定身份或设备能力；同一设备归并的底层实体随设备一起更新空间映射。 |
| SP-011 | 空间属于家庭配置，设备离线时仍可调整；底层映射同步失败时保留产品侧设置并后台重试，不提示为设备控制失败。 |
| SP-012 | 空间调整成功后同步到首页、设备详情、电视端和 AI；一般批量调整逐台返回结果，空间删除必须保持“迁移全部成功后再删除”的完整性。 |

家庭管理员拥有空间管理权限；家庭成员可以查看空间和使用本人已授权的空间设备，但不能新增、重命名、排序、删除空间或调整设备归属。

## 17. Home Assistant 接入模型

### 17.1 产品映射

依据 Home Assistant 官方概念：集成负责连接品牌或平台；设备是一个或多个实体的逻辑组合；实体承载状态、传感数据或可执行动作；区域用于组织物理空间。

产品侧采用以下映射：

| Home Assistant 概念 | 产品侧表达 |
| --- | --- |
| Integration／配置实例 | 接入来源与接入连接；当前云端品牌在界面中称“小米账号”“涂鸦账号” |
| Device | 用户看到的一台设备；保持稳定身份 |
| Entity | 设备能力和状态来源，不直接展示原始实体标识 |
| Area | 家庭空间，可与产品空间同步但由产品界面统一管理 |

同一设备可能包含多个实体，前端必须先归并为设备，再按能力展示。不同集成提供的设备种类和能力可能不同，不能因品牌授权成功就宣称所有设备和全部原厂功能均可使用。

### 17.2 通用接入闭环

| 编号 | 需求 |
| --- | --- |
| AC-001 | “添加设备”先选择接入来源，再选择该来源下已有接入连接；没有可用连接时必须先完成新账号绑定。小米、涂鸦不是固定系统上限。 |
| AC-002 | 新来源使用统一外壳承载品牌说明、前置条件、授权步骤、等待、成功、失败和取消。 |
| AC-003 | 授权完成只表示连接建立；仍需同步设备并识别支持情况。 |
| AC-004 | 同步结果按“可添加、已添加、部分能力可用、暂不支持、同步失败”区分。 |
| AC-005 | 用户选择设备并完成接入后，必须确认名称和主要空间；可选择已有空间或当场新增空间，批量添加允许逐台调整或统一安置。 |
| AC-006 | 多设备添加需逐台返回结果；部分失败不撤销已成功设备，并可只重试失败项。 |
| AC-007 | 同一品牌允许多个连接，每个连接需有可区分名称、授权状态、设备数量和最近同步时间。 |
| AC-008 | 解除连接前列出受影响设备；解除后设备不可继续显示在线或可控。 |
| AC-009 | 重新授权或重新连接后尽量保持原设备身份、空间和用户配置；无法可靠识别时交由用户确认。 |
| AC-010 | “设备接入成功”只表示设备关系已建立；名称和空间保存成功后才记为“设备添加完成”，并进入首页、电视端和 AI 的正常设备范围。 |
| AC-011 | 接入成功后中断配置的设备记为“待完成配置”，保留来源账号和已识别能力；管理员再次进入时从空间配置继续，不要求重复授权。 |
| AC-012 | 设备设置允许后续修改名称、空间和权限，但不得直接切换设备的来源账号；更换来源需说明影响，移除原设备关系后从目标账号重新接入。 |
| AC-013 | 同一设备被当前家庭的其他连接发现时，需标为“已添加”或提示可能重复；只有稳定标识足以确认时才复用原设备身份。 |
| AC-014 | 移除后的设备在再次同步时可恢复为“可添加”，但不得自动重新加入；重新绑定同一账号时，历史名称与空间只能在识别可靠且管理员确认后恢复。 |

### 17.3 小米当前接入要求

以下流程依据 Home Assistant 2026.9.2 的 Xiaomi Home 官方文档，真实试点仍需用目标账号和型号验证：

1. 用户先在 Mi Home App 中完成设备添加；不假设设备只在 Roborock 等品牌独立 App 中也能被当前集成发现。
2. 小程序选择“小米”后，说明前置条件，并让用户确认 Xiaomi Home App 使用的服务器区域。
3. 通过受保护的授权步骤完成小米账号连接；用户凭据不得出现在电视二维码或普通日志中。
4. 产品服务端驱动对应 Home Assistant 配置流程，等待连接结果。
5. 同步集成实际返回的设备和能力，显示可添加、部分支持或暂不支持。
6. 用户选择设备、命名并分配空间后完成接入。

Home Assistant 文档同时表明：部分小米设备可被自动发现，部分型号需要凭据、区域、令牌或其他配置，支持范围因设备型号而异。因此首期不能使用“登录小米账号即可接入全部米家设备”的承诺。

### 17.4 涂鸦当前接入要求

以下流程依据 Home Assistant 2026.9.2 的 Tuya 官方文档：

1. 用户需已有 Tuya Smart 或 Smart Life App 账号，并至少在该 App 中添加一台设备。
2. 小程序提供获取 User Code 的图文引导：进入 App 的“Me／设置／Account and Security”查看 User Code。
3. 用户提交 User Code 后，产品服务端发起对应 Home Assistant 配置流程并生成授权二维码。
4. Home Assistant 官方当前流程要求另一块屏幕展示授权二维码，再由手机中的 Tuya Smart／Smart Life App 扫描。产品首选流程改为：小程序全屏展示二维码，用户保存图片，根据步骤提示前往涂鸦 App，并在扫码页从相册选择该图片；返回小程序后自动查询授权结果，并保留手动检查入口。微信小程序不得预设为可直接拉起任意第三方 App。
5. 用户已确认涂鸦 App 支持从相册识别二维码，首期按此作为正式主流程。开发联调仍需覆盖目标 iOS／Android 与 Tuya Smart／Smart Life 版本兼容、图片保存权限和二维码过期；异常时提示重新保存，不把电视或第二屏作为默认步骤。
6. 技术侧同步验证涂鸦官方 App 深链、Universal Link 或 OAuth。只有官方支持、授权范围明确且真实账号验证通过后，才可将一键跳转授权替换为主流程；不能根据二维码内容自行拼接未公开深链。
7. 授权成功后同步设备，并区分完整支持、部分能力可用和暂不支持。
8. 用户之后在 Tuya Smart／Smart Life App 新增设备时，小程序的“同步设备”操作需触发对应集成重新加载，再展示新结果。

当前官方 Tuya 集成不支持锁和遥控器平台，且官方 SDK 不一定暴露 Smart Life 中的全部功能。产品需按 Home Assistant 实际返回能力展示，不用原厂 App 中存在某功能作为可控依据。

## 18. 消息中心

消息中心既保存应用内消息，也承接经用户允许的必要外部通知。首期不把每次状态变化或控制成功都推送给用户。前台不展示分类入口，统一使用一个消息列表；分类仅由后台用于权限、排序、去重、跳转和通知策略。

### 18.1 后台消息类型

| 类型 | 示例 | 默认接收人 |
| --- | --- | --- |
| 待处理 | 小米或涂鸦授权失效、家庭主机持续断连、电视接续任务失败 | 家庭管理员 |
| 设备问题 | 设备持续离线、状态长期未知、设备同步失败 | 管理员及具备该设备权限的成员 |
| 接入与变更 | 发现新设备、设备部分支持、账号解除、成员变化 | 家庭管理员 |
| 系统通知 | 服务维护、安全提醒、功能更新 | 受影响用户 |

### 18.2 功能需求

| 编号 | 需求 |
| --- | --- |
| MSG-001 | 底部“消息”显示未读数量；页面只有一个列表，不提供用户可见的分类标签或分类分页。列表按需要处理优先、其余按时间倒序排列。 |
| MSG-002 | 每条消息只显示未读圆点、标题、一行简要文案和时间，不在列表中堆叠类型、级别、家庭、关联对象或多个按钮。 |
| MSG-003 | 点击需要处理的消息后直接进入对应账号、设备或说明页，并在目标页提供唯一明确动作，如“重新授权”“同步设备”“查看设备”。 |
| MSG-004 | 普通通知进入简洁详情；需要处理的消息进入关联对象后，返回消息列表时保留原位置。 |
| MSG-005 | 同一问题在短时间内重复发生时合并更新，避免重复轰炸；恢复后更新为已恢复。 |
| MSG-006 | 设备短暂波动不立即产生问题消息；具体持续时间在真实试点中校准。 |
| MSG-007 | 消息区分未读、已读、待处理、已解决；已读不等于问题已解决。 |
| MSG-008 | 外部推送只用于用户已允许且确需及时处理的事项；普通系统信息只进入消息中心。 |
| MSG-009 | 用户可设置设备问题、账号问题和系统通知偏好；涉及账号失效等管理员必需事项不可完全静默。 |

P0 演示应用内消息和问题恢复闭环；P1 在微信能力与用户授权允许时验证订阅通知，不能把订阅授权或送达视为默认成立。

### 18.3 手机视觉与交互基线

手机端采用 Apple 风格的系统化设计语言，具体规范由独立的[设备中心手机小程序设计系统](device-center-mobile-design-system.md)拥有。产品侧要求为：浅色与留白优先、大标题与分组层级、克制圆角和阴影、系统化开关／滑杆／列表、半透明底部标签栏与弹层、方向一致的页面转场、适度弹簧感和可选触觉反馈。不得直接复制 Apple 商标或未授权的专有图标资源。

## 19. AI 助手

首期以文字聊天为主，服务范围限于当前家庭的设备查询、状态解释和低风险控制，不承担开放领域问答或账号配置。

### 19.1 支持能力

- 查询：“客厅有哪些设备在线？”“卧室温度是多少？”
- 单设备控制：“打开客厅落地灯”“把卧室床头灯亮度调到 40%”。
- 空间控制：“关闭客厅所有灯”。
- 状态解释：“为什么客厅窗帘控制不了？”
- 结合消息处理：“涂鸦账号需要重新授权，带我去处理”。

### 19.2 对话闭环

| 编号 | 需求 |
| --- | --- |
| AI-001 | 助手默认使用当前家庭上下文；家庭切换后清除不再适用的设备指向。 |
| AI-002 | 只允许访问当前用户有权查看或控制的空间和设备。 |
| AI-003 | 设备名称、空间或动作存在歧义时先澄清，不猜测执行。 |
| AI-004 | 空间批量控制在执行前展示目标数量并确认；高影响设备不在首期开放 AI 控制。 |
| AI-005 | 每个控制动作使用与手动控制相同的连接、授权、执行和回执规则。 |
| AI-006 | 回复需区分理解结果、正在执行和最终结果；部分成功时逐项说明。 |
| AI-007 | 设备离线、授权失效或能力不支持时解释具体原因，并提供可执行下一步。 |
| AI-008 | 会话中的控制动作需形成必要记录；普通聊天内容的保存范围后续结合隐私方案确认。 |

Home Assistant Conversation 支持通过实体名称和区域执行开关等意图，也允许扩展语句。P1 可复用其设备与区域控制能力；中文表达、产品别名和数值调节的实际覆盖必须通过真实语料验证。P0 使用已确认的中文命令集完整演示，P1 对未覆盖表达提供产品侧语句扩展或澄清，不把语言模型回答直接视为控制成功。

## 20. 最小产品服务端与扩展

真实家庭首期确定建设最小产品服务端，职责包括：

- 小程序身份、家庭、成员和两级角色权限。
- 接入来源、多个连接、产品设备身份、能力和空间关系。
- 驱动 Home Assistant 集成配置、重新授权、同步和解除，并保存产品侧结果。
- 家庭外控制请求、处理状态、设备回执和跨端状态同步。
- 电视扫码任务的创建、校验、过期和结果同步。
- 消息生成、接收范围、处理状态和必要外部通知。
- AI 会话上下文、权限校验、控制确认与结果返回。
- 关键账号、成员、设备和远程控制操作的必要记录。

首期不建设自研设备协议与品牌驱动、替代 Home Assistant 的控制引擎、通用自动化平台、用户网页后台、设备商城或开发者开放平台。

后续扩展时，应能增加新的接入来源、成员权限、消息类型、自动化／场景、更多 AI 能力和完整康养移动端，而不更换家庭、账号、设备、能力、指令和消息的基础关系。

## 21. 电视与手机共用演示数据

P0 使用电视端现有的同一家庭、空间、账号和 12 台设备样本：涂鸦 9 台、小米 3 台；包含灯、窗帘、温湿度传感器及陈展设备，保持在线、离线、状态未知、授权失效、主机断连、失败和超时场景。

| 编号 | 需求 |
| --- | --- |
| DEMO-001 | 两端显示相同的设备身份、名称、空间、账号归属、能力和初始状态。 |
| DEMO-002 | 任一端成功控制后，另一端重新进入或刷新时展示相同结果。 |
| DEMO-003 | AI 控制与手动控制更新同一状态；失败和超时不覆盖上次确认状态。 |
| DEMO-004 | 账号授权失效、设备离线等测试状态同时影响两端，并产生对应消息。 |
| DEMO-005 | 手机完成电视发起的添加、授权或设置任务后，电视展示对应完成结果。 |
| DEMO-006 | 演示者可切换测试情境，但访客界面不出现“Mock”或开发测试字样。 |
| DEMO-007 | Demo 版在手机右下角、底部标签栏上方提供“演示状态”悬浮球；点击后以底部面板切换预设情境并显示当前情境。正式家庭版本隐藏。 |
| DEMO-008 | 首期预设覆盖全部正常、无设备、家庭连接中断、账号授权失效、部分设备离线、状态未知、控制失败、控制超时、部分支持、二维码过期及管理员／成员角色。 |
| DEMO-009 | 一次只启用一个主情境，并提供“恢复默认”；角色可作为独立维度。切换后同步手机、电视和消息，且不得向真实设备发出指令。 |

## 22. P0 与 P1 一体化交付

### 22.1 P0：完整可交互演示

- 四个底部入口及全部核心页面可操作。
- 小米和涂鸦按各自真实步骤模拟授权、同步、部分支持和失败。
- 设备手动控制、AI 控制、消息产生与处理形成闭环。
- 手机与电视共享设备状态并可共同演示。
- 家庭、管理员和成员权限可演示。
- 空间新增、重命名、排序、删除、未分配和设备迁移形成完整演示闭环。
- 添加设备可完整演示“选择或绑定账号 → 选择设备 → 接入成功 → 选择或新增空间 → 添加完成”，并可从“待完成配置”恢复。
- 右下悬浮球可切换预设异常、状态和角色，并恢复默认；正式产品模式不显示。

### 22.2 P1：真实链路演示与试点

P1 采用与 P0 相同的产品界面和流程。没有真实账号、硬件或外部授权条件时，可通过可替换的接入模拟完成完整链路演示；对外必须明确演示与真实接入边界。

具备条件后，在一个试点家庭验证：

- 管理员和家庭成员真实登录及权限。
- 小米、涂鸦至少各一个真实连接，并记录其型号和能力范围。
- 灯、窗帘、传感器等已验证设备的状态和控制。
- 家庭外控制、真实结果同步、账号重新授权和消息通知。
- 电视与小程序真实扫码接续。
- AI 中文命令在真实设备、空间和别名下的成功、澄清、失败与部分成功。

P0 和 P1 应由同一套页面、状态和业务规则承接；真实能力通过替换接入与数据来源启用，不再重做一套用户流程。

## 23. 手机小程序验收

1. 用户可在首页、助手、消息、我的四个入口间稳定切换，家庭上下文保持一致。
2. 管理员可完成小米和涂鸦两类不同接入流程；成员不能管理接入连接。
3. 涂鸦同手机保存二维码／相册识别、小米区域选择、同步、部分支持和失败路径均有明确交互；开发联调覆盖目标 App、系统组合、图片权限和二维码过期。
4. 设备能力由实际接入结果决定；只读设备不出现开关，部分支持设备不冒充全部可用。
5. 手动和 AI 控制均覆盖处理中、成功、失败、超时、离线和权限不足。
6. 消息能从问题产生进入关联处理页，并在问题解决后更新状态。
7. 电视与手机共用 12 台演示设备，跨端控制和配置结果一致。
8. P0 可独立完成全流程演示；P1 在没有真实条件时可模拟，在具备条件时无需改页面即可切换真实链路。
9. 用户界面不出现 Home Assistant、实体标识、配置条目或开发测试字样。
10. 管理员可在一次编辑中把多台设备分别调整到不同空间，保存结果同步到电视与 AI 空间语义；成员不能修改。
11. 消息页面保持单一列表，每项仅显示未读状态、标题、简要文案和时间，后台分类不暴露为前台导航。
12. 手机页面、组件和动效符合独立手机设计系统的 Apple 风格基线，并覆盖减少动态效果和最小触控尺寸。
13. 管理员可新增、重命名、排序和删除空间；删除含设备的空间时先完成迁移，空间变化不会改变设备来源账号和能力。
14. 添加设备必须选择或绑定对应账号；设备接入成功后必须选择或新增空间，保存名称与空间后才进入正常设备列表。
15. 配置中断的设备显示为“待完成配置”，重新进入后从空间配置继续；设备设置不能直接切换来源账号。
16. 账号失效保留设备名称与空间；解除账号、移除设备、删除空间分别按影响范围处理，不产生未说明的连带删除。
17. Demo 悬浮球可切换预设情境并恢复默认，情境同步影响手机、电视和消息，不向真实设备发送指令；正式家庭版本不显示该入口。
